# GT_Telemetry

Локальная телеметрия Gran Turismo 7. Код продукта лежит в `apps/`.

Сервер: `apps/server` (Python). Страница: `apps/web` (TypeScript, React, Vite). Данные кругов позже пишутся в `data/`.

Версия `0.6.0` добавляет запись внутреннего и внешнего края трассы с высотой, имя трассы и прежнюю живую панель, когда задана переменная окружения `GT7_PLAYSTATION_IP`. Имя переменной есть в `.env.example`. Заполненный `.env` в репозиторий не класть. Адрес в код не зашивается.

Если адрес пустой или принятый пакет старше одной секунды, страница пишет, что связи нет (`There is no link`). Полосы пустые, числа — длинное тире. Старые проценты на экране не остаются.

## Сервер

Из каталога `apps/server`:

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
GT7_PLAYSTATION_IP=<адрес PS5> .venv/bin/python -m gt_telemetry.main
```

HTTP и WebSocket только на `127.0.0.1:8787`. Проверка: `GET /health`. Поток в браузер: `/ws`.

UDP: heartbeat — байт `A` на порт `33739` адреса из `GT7_PLAYSTATION_IP`, примерно раз в секунду. Приём пакетов — порт `33740`.

## Страница

Из каталога `apps/web`:

```bash
npm install
npm run dev
```

Открыть `http://127.0.0.1:5173/`.

## Как работать

Отдельный чат на каждую роль. В чат подключено ровно одно правило роли:

| Чат | Правило | Контракт |
| --- | --- | --- |
| Architect | `.cursor/rules/architect-agent.mdc` | `.ai/architect/ROLE.md` |
| Develop | `.cursor/rules/develop-agent.mdc` | `.ai/develop/ROLE.md` |
| Review | `.cursor/rules/review-agent.mdc` | `.ai/review/ROLE.md` |
| SysAdmin | `.cursor/rules/sysadmin-agent.mdc` | `.ai/sysadmin/ROLE.md` |
| Designer | `.cursor/rules/design-agent.mdc` | `.ai/design/ROLE.md` |

Промпт от Architect вставляется целиком в чат нужной роли. Чат без правила роли ничего не выполняет: он только говорит, куда вставить промпт.

Общие правила включены всегда: язык, маршрутизация ролей, отчёт, один блок `text` для чужого промпта, запрет переименовывать чат.

## Порядок фичи

1. Architect разрешает задачу и отдаёт английский промпт Developer.
2. Developer делает ветку от `main`, коммитит работу и останавливается на промпте Reviewer.
3. Reviewer выносит вердикт и не правит код.
4. Architect вливает ветку в `main` (fast-forward), удаляет ветку и обновляет состояние.
5. SysAdmin — только если Architect отдельно разрешил операцию, и только когда `main` чистый.
6. Designer — только по задаче `DESIGN-*` от Architect.

`Approved` от Reviewer ещё не значит «задача закрыта». Закрыта она после merge и уборки веток.

Пока предыдущая задача не влита или дерево грязное, следующую разработку не начинать.

## Что сделать сейчас

Запустить сервер и страницу, как выше. Пока с консоли приходят свежие пакеты, на экране живые газ, тормоз, скорость, обороты, передача, номер круга, время прошлого круга, линия пути и стрелка по ходу движения.
